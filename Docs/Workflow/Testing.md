# Testing Rules

## 1. 기본 원칙

테스트는 코드가 의도한 대로 동작하는지 확인하는 과정입니다.

- 테스트하지 않은 기능을 정상 작동한다고 판단하지 않습니다.
- 실제 테스트 결과와 코드 검토 결과를 구분합니다.
- 확인하지 않은 성능 수치를 임의로 작성하지 않습니다.
- 오류가 발생하면 원인을 확인하고 사용자에게 보고합니다.

## 2. 테스트 단계

테스트는 다음 단계로 구분합니다.

### 2.1 코드 검토

- 코드의 문법과 논리적 오류를 확인합니다.
- 데이터 흐름과 실행 순서를 검토합니다.
- 기존 시스템과 충돌하거나 중복되는 부분이 있는지 확인합니다.

코드 검토만 수행한 경우 실제 실행 테스트를 완료했다고 표현하지 않습니다.

### 2.2 컴파일 테스트

- Unity Console의 컴파일 오류를 확인합니다.
- 오류가 발생하면 관련 코드와 원인을 분석합니다.
- 컴파일 성공 여부를 실제 확인한 경우에만 성공으로 보고합니다.

### 2.3 기능 테스트

- Unity Play Mode에서 기능이 의도한 대로 동작하는지 확인합니다.
- 정상 상황뿐 아니라 예외 상황도 고려합니다.
- 다른 시스템에 영향을 주는지 확인합니다.

### 2.4 성능 테스트

- GC Alloc, CPU 사용량, 메모리 사용량 등을 필요에 따라 확인합니다.
- 최적화 전후의 성능은 동일한 조건에서 비교합니다.
- 실제 측정하지 않은 성능 개선 수치를 작성하지 않습니다.

## 3. 오류 및 문제 대응

오류가 발생하면 다음 순서로 진행합니다.

1. 오류 메시지와 발생 위치를 확인합니다.
2. 오류가 발생한 원인을 분석합니다.
3. 수정 방법과 예상되는 영향을 설명합니다.
4. 필요한 경우 사용자 승인을 받습니다.
5. 수정 후 동일한 조건으로 다시 테스트합니다.

문제를 해결하지 못한 경우 해결된 것처럼 보고하지 않습니다.

## 4. 테스트 결과 보고

작업 완료 시 다음 내용을 구분하여 보고합니다.

- 코드 검토: 완료 / 미완료
- Unity 컴파일: 성공 / 실패 / 미실행
- 기능 테스트: 성공 / 실패 / 미실행
- 성능 테스트: 측정 결과 / 미측정
- 발견된 문제: 내용 및 해결 여부
- 추가 확인이 필요한 사항

테스트를 실행할 수 없는 환경이라면 그 이유를 명시합니다.

## 5. 테스트 범위

- 현재 작업과 직접 관련된 기능을 우선 테스트합니다.
- 기존 기능에 영향을 줄 가능성이 있으면 연관된 기능도 확인합니다.
- 테스트하지 않은 영역까지 정상 작동한다고 판단하지 않습니다.
- 불필요하게 전체 프로젝트를 변경하거나 테스트하지 않습니다.
